# 检查点重分片网页（训练机换卡）

训练机换卡后，检查点要交给不同数量的 rank。本应用用 **Flask + NumPy** 实现重分片：
旧卷上的检查点按 rank 存放（参数 `param`、同段的 Adam 一阶 `adam_m` / 二阶 `adam_v`
状态和训练步 `step`），重分片时把各 rank 的数组按 rank 顺序拼成全局数组，
**三个数组按同一套全局下标连续等分，余数依次分给低 rank，每片都带训练步**，
按新 rank 数写到新卷并提供 NumPy 文件下载。

另有两个**归档回退位**：可把当前不依赖旧卷的发布存档、删除任一留档；旧卷卸载或
当前发布换版后，仍可从所选留档在线重分片并下载。

## 网页操作

1. **旧卷状态**：内置样例检查点——正常 3 rank（step 42000）、同数组仅 step 43000
   的第二版、训练步不一致、缺片。可**模拟卸载**、**挂回同一卷**、
   **挂载不同卷**（卷 ID 不符不恢复可读性）。
2. **重分片**：选检查点，填**新 rank 数**和**新卷容量（字节）**，勾选
   **续训时能否挂旧卷**（勾选则发布结果依赖旧卷）；另有"模拟写失败"开关。
3. **新卷与当前发布**：容量、当前占用（发布 + 暂存）、**分片文件占用峰值**、
   发布记录与可读性，按新 rank 下载 npz。
4. **归档（两个回退位）**：
   - **归档容量（字节）**：只改容量，已有留档与占用照旧。
   - **将当前发布存档**：只允许存当前不依赖旧卷的发布；两个位，第三份被拒。
   - 页面显示**入档后实际保留的数组数据字节数**（去重后数据块字节，不含索引元数据），
     分档列出"本次新增数据"与"独占（删档释放）"。
   - **删除**任一留档，立即释放仅该档使用的数组数据；保留档无需重写。
   - **从留档在线重分片**：选留档 + 新 rank 数，仅从该档读数组和训练步，
     重新分片、回读校验后生成下载；不读旧卷、不读当前发布。
5. **操作历史**：每次重分片的结果与失败原因；归档操作另有可展开记录。

## 归档存储与语义

- 存储布局：`archive/store/<前2位>/<sha256>` 为数据块，`archive/archives/<id>/index.json`
  为留档索引，`archive/state.json` 记录归档容量、两个槽位与操作历史。
- **切块**：三个数组各自按固定 **4 KiB** 切块，块名是内容 sha256。数组是全局字节流，
  与 rank 切法无关；训练步只放在索引里。
- 因此**仅训练步不同**或**仅 rank 切法不同**的两版，第二个留档新增数组数据为 **0 B**。
- **同 dtype、同长度的数组只有一段连续 B 字节变化**时，最多弄脏
  `ceil(B/4096)+1` 个块，新增占用 ≤ `B + 2×4096 = B + 8 KiB`。
  4 KiB 块只在块内变化时最优（常为 1 块）。
- **容量**只计算去重后的数组数据块字节。建归档先算新增字节，超额直接失败；
  写入中途失败会删掉本次新写的块。两种失败都**不改动已有留档、归档容量与占用**。
- **删档**：先把索引挪走并落盘，再删掉无留档引用的块，最后清理索引；
  保留留档的 `index.json` 与数据块不重写（自测用 inode/mtime 验证）。
- **读档**：逐块 sha256 校验并核对长度；重分片后回读校验训练步、长度和内容才给下载。
  导出文件只保留最近一次，删档时一并清理。

## 失败语义（重分片发布）

- 读源前要求旧卷可读（已挂载且为同一卷）；源校验**缺片**、**训练步不一致**直接失败。
- 逐片写入暂存区，**上一套发布 + 本次暂存一起计入新卷容量**，超限即失败。
- 全套暂存分片在**指定挂载条件下回读校验**（存在性、训练步、长度、与源拼接一致）才发布。
- **缺片、训练步不一致、超额、模拟写失败**时：清理暂存、**保留上次发布结果**、历史记录原因。
- 发布时若声明"续训可挂旧卷"，结果标记为依赖旧卷：**旧卷卸载后标为不可读，
  挂回同一卷（卷 ID 相同）后恢复**；挂不同的卷不恢复。不依赖旧卷的结果不受卸载影响。

## 已实现 / 已验证

- 按 rank 存参数 + 同段 Adam 一阶/二阶状态 + 训练步的旧卷样例（含缺片、训练步不一致）
- 三个数组同一全局下标连续等分、余数给低 rank、每片带训练步
- 新卷容量、占用与峰值（上一套 + 本次暂存计入容量）；四类失败保留上次发布并清理暂存
- 模拟卸载 / 挂回同一卷 / 挂载不同卷；依赖旧卷的结果卸载后不可读、挂回恢复
- **两个归档回退位**：存档、删档、归档容量；页面显示入档后实际保留的数组数据字节
- **去重增量**：仅 step 不同 / 仅 rank 切法不同 -> 新增 0 B；
  1500 B 连续改动实测每数组新增 8192 B（上限 9692 B），满足 `改动段 + 8 KiB`
- 归档超额 / 写失败均保留已有留档与占用；删档立即释放独占数据、保留档索引与块未被重写
- 旧卷卸载后、当前发布换版后，均可从所选留档重分片并下载（内容与全局下标核对一致）
- `tests/selftest.py` **25/25 通过**；真实 HTTP 冒烟覆盖存两个位、第三份被拒、
  删档后释放、从留档导出并下载、容量设置保留
- `docker-compose.yml` 通过 YAML 解析与关键字段校验

## 未完成 / 限制

- 本环境无 Docker 守护进程，**镜像构建与 `docker compose up` 未实际执行**，仅静态校验
- 卷为本地目录模拟，非真实挂载点；挂载状态存于 `mount.json`
- 重分片 / 读档为全量读入内存，未做流式/mmap；4 KiB 块逐块读写，超大检查点需分块流水线
- 归档只保留**两个**回退位（按需求固定）；槽位占满需先删
- 单进程串行（锁保护），无任务队列与并发；多进程共用 `DATA_DIR` 未加文件锁
- 导出文件只保留最近一次，且不计入归档容量
- 回读校验靠 np.load + 拼接比对；归档块有 sha256 校验，新卷分片本身未做逐片校验和
